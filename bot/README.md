# Olim Polvon — Telegram-бот + API сайта (Cloudflare Workers + D1)

Один Worker `olim-bot` делает две вещи:
- принимает вебхук Telegram на `/tg`. Там гости (меню, корзина, заказ, бронь, чек, AI), сотрудники и роли;
- отдаёт API для сайта на `/api/*`: заказ, бронь, статус, живая геолокация, чек, вход в админку.

Заказы, брони, пользователи, роли, чеки и очередь сообщений лежат в D1 (`schema.sql`).
Меню берётся из `src/menu_data.py`. Скрипт `src/make_bot.py` (его запускает `build.sh`) генерирует `src/menu.gen.js` и JPEG-копии фото в `assets/menu/tg/`.

## Запуск с нуля (терминал)

```sh
cd bot
npm install
npx wrangler login
npx wrangler d1 create olim-bot          # скопируйте database_id в wrangler.toml
npm run db:remote                        # создаёт таблицы

# секреты: в git их нет
npx wrangler secret put BOT_TOKEN        # от @BotFather
npx wrangler secret put WEBHOOK_SECRET   # любая длинная случайная строка: openssl rand -hex 24
npx wrangler secret put SITE_KEY         # ещё одна случайная строка, та же пойдёт в Google Apps Script
npx wrangler secret put ADMIN_PASS       # новый пароль админки сайта (старый 129091 больше не работает)
npx wrangler secret put GROQ_KEY
npx wrangler secret put AI_KEY           # Gemini, запасной

# в wrangler.toml → [vars] впишите DEV_IDS = "ваш Telegram id" (узнать: напишите боту /id)
npm run deploy

# один раз: ставим вебхук и меню команд
curl -X POST https://olim-bot.abduraxmanov349.workers.dev/setup -H "X-Site-Key: <SITE_KEY>"
```

После этого напишите боту `/start`. У id из `DEV_IDS` сразу будет роль «разработчик», а дальше `/panel` → «Роли».

## Google Apps Script (пересылка с сайта, потому что workers.dev заблокирован в Узбекистане)
1. Вставьте новый `worker/Code.gs` в проект Apps Script.
2. В Project Settings → Script Properties добавьте `BOT_URL = https://olim-bot.abduraxmanov349.workers.dev` и `SITE_KEY` (тот же, что в wrangler).
3. «Развернуть → Управление развертываниями → Новая версия». Адрес /exec останется прежним.

Сайт сначала стучится в Google, а если тот не ответил — в Worker напрямую (адреса в `SITE["api_endpoint"]` в `build.py`).
Когда появится свой домен на Cloudflare, повесьте Worker на `api.<домен>` (Workers → Settings → Domains & Routes) и поставьте этот адрес первым. Тогда Google будет не нужен и ответ придёт быстрее.

## Роли
| Роль | Что получает |
|---|---|
| `orders` — приём заказов | новые заказы (сайт и бот), живую геолокацию, чеки к заказам, кнопки статусов |
| `bookings` — приём броней | заявки на стол, кнопки «Подтвердить / Перезвоню / Отклонить / Назначить стоимость», чеки к броням |
| `checker` — проверяющий | всё сразу (уведомления можно выключить в /panel), статистику, недоставленное, отчёт в 23:05, управление ролями |
| `dev` — разработчик | всё, что у проверяющего, плюс `/health`, `/logs`, `/test` (тест-режим: новые заказы уходят только разработчикам) |

Назначить роль можно двумя способами: /panel → «Роли» → «➕ роль» (одноразовая ссылка на 48 часов, сотрудник просто открывает её) или командой `/grant <id> orders|bookings|checker|dev`.
Если ни у кого нет нужной роли, заказы уходят разработчикам: так они не теряются.

## Настройки, которые даст владелец (без передеплоя, командой в боте от проверяющего)
```
/set card 8600 1234 5678 9012
/set card_owner Имя Фамилия
/set booking_fee 100000      (пусто — сотрудник называет цену для каждой брони)
/set notes Скидка 10% навынос до 31 декабря
```
Акции, сохранённые в админке сайта, Google тоже пересылает боту.

## Почему не теряются сообщения
- Каждый заказ, бронь и чек получает `id` на клиенте. Повторная отправка возвращает тот же номер и не создаёт дубль.
- Сайт держит неотправленное в `localStorage` (`polvon_outbox`) и повторяет отправку (3 с → 5 мин), пока сервер не ответит `ok`.
- Каждое сообщение сотрудникам сначала пишется в таблицу `outbox`, а потом отправляется. Cron раз в минуту повторяет неудачные отправки с паузами от 30 с до 4 ч. Если Telegram ответил 429, ждём столько, сколько он просит. Если сообщение так и не ушло, проверяющие получают предупреждение и видят его в `/undelivered`, там же кнопка «Повторить всё».
- Почему не Queues и не Durable Objects: заказов немного, данные и так в D1, а таблицу владелец может открыть и посмотреть, что не дошло. Из очереди этого не видно.
